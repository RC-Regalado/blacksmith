## Scope delivered

`ai_assistant/application/runtime.py`: `AgentRuntime._finish_with_synthesis()` remediates FINDING-003 (a turn that exhausts its tool budget previously returned a raw rejection artifact instead of a real answer). It makes exactly one additional `model.chat()` call — never counted as a tool round, never executing a tool — explicitly instructing the model to produce a final answer from evidence already gathered in the conversation. If that response still contains a tool call (the model ignoring the instruction), the runtime falls back to a deterministic, non-LLM `_exhaustion_summary()` that lists only `tool_name` + `status.value` per attempt — never arguments, content, or fingerprints, preserving the existing sanitization guarantees.

This path is exercised the same way loop-exhaustion and progress-guard-stop are exercised in the M5.2.11 tests above (`test_runtime_stops_once_tool_loop_budget_is_exhausted`, `test_runtime_rejects_tool_round_once_budget_exhausted`, `test_runtime_stops_via_progress_guard_after_repeated_failures`): each asserts the final `Message.content` is real synthesized text (e.g. "Here is a summary of what I found."), not the old fixed string `"Tool round limit reached; no additional tool was executed."`, which no longer exists anywhere in production code (confirmed by grep during independent test-agent review).
