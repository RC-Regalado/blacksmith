# M5.2.13 — End-to-End Observability

## Status

automatically-accepted

## Scope

Remediate FINDING-009 (tool observability lacks interaction-level correlation) and close the residual gap in FINDING-008 (context/generation limits not coordinated/observable) that M5.2.5/M5.2.6 left open. Correlate context/retrieval, model request/response, tool request/result, recovery, budgets, final synthesis and interaction completion — all sharing one per-turn `interaction_id` — per ADR-070/ADR-071. Implemented together with M5.2.14 (expanded metrics) since both extend the same new event stream; full implementation evidence for both is recorded here, `M5.2.14.md` is a pointer.

## Implementation evidence

- `ai_assistant/domain/tools.py`: new `InteractionStage` StrEnum (`context_retrieval`, `model_request`, `model_response`, `final_synthesis`, `interaction_completed`) and `InteractionLogEvent` frozen dataclass — a sibling of the existing `ToolCallLogEvent`, validated non-blank `interaction_id`/`session_id`/`provider`/`model`.
- `ai_assistant/application/ports/tools.py`: new `InteractionDiagnosticLogger` ABC port.
- `ai_assistant/application/tool_diagnostics.py`: new `InteractionDiagnostics` helper (no-op when `interaction_id` is `None`, swallows sink exceptions — diagnostics must never break a turn) and `NullInteractionDiagnosticLogger`.
- `ai_assistant/infrastructure/tool_diagnostics.py`: new `JsonlInteractionDiagnosticLogger`, deliberately writing to the **same physical file** as the existing `JsonlToolDiagnosticLogger` (shared `_filename(model, session_id, date)` helper) — an operator can reconstruct one complete interaction by grepping one file for one `interaction_id`, the literal FINDING-009 remediation.
- `ai_assistant/application/runtime.py`: `AgentRuntime` now emits `InteractionLogEvent`s at every stage of a turn via a new `_call_model()` helper (wraps every `self.model.chat(...)` call with MODEL_REQUEST/MODEL_RESPONSE events, tracking `_model_calls_used`/`_last_model_response`), `_record_context_retrieval()` (CONTEXT_RETRIEVAL, after context assembly), the existing `_finish_with_synthesis()` (now also emits FINAL_SYNTHESIS), and a new `_complete_interaction()` (INTERACTION_COMPLETED, on both success and exception paths of `respond()`). The "direct tool call from raw JSON user input" branch was refactored from an early `return` to falling through to the shared completion logic (previously it silently skipped the "agent turn completed" log line and would have skipped diagnostics too — now fixed as part of unifying the exit path).
- **FINDING-008 closure**: `ConversationContextService._budget` was made public (`self.budget`, safe since `ConversationContextBudget` is frozen/immutable). `AgentRuntime` gained `ollama_num_ctx`/`ollama_num_predict` fields (wired from `AppConfig` in `bootstrap/container.py`, reusing M5.2.5's existing config, no new env var). `_record_context_retrieval()`'s payload now includes `provider_context_window`, `reserved_output_length`, `max_input_length` (from the application-level budget) alongside `model_num_ctx`/`model_num_predict` (Ollama-side) in one observable per-turn record — the operator no longer has to cross-reference two independently-configured numbers by hand.
- `ai_assistant/bootstrap/container.py`: wires `JsonlInteractionDiagnosticLogger(app_config.tool_log_dir)` and `ollama_num_ctx`/`ollama_num_predict` into `AgentRuntime(...)`.
- **Redaction bug found and fixed twice during implementation** (not a change to the shared `redact_sensitive()` itself, which does substring matching on sensitive keywords including "token"/"prompt" — judged too risky to change broadly in this milestone): payload dict keys `prompt_tokens`/`output_tokens` were renamed to `input_length`/`output_length`, and later `reserved_output_tokens`/`max_input_tokens` were renamed to `reserved_output_length`/`max_input_length`, in the JSONL payload construction only — never in the `ModelResponse`/`ConversationContextBudget`/`InteractionMetrics` dataclass field names or the CLI print labels. Both occurrences were caught by live smoke-testing the real wiring (not just in-memory-fake-sink unit tests, which do not exercise `redact_sensitive` at all and would pass regardless of the bug) and are now covered by dedicated regression tests that round-trip through the real `JsonlInteractionDiagnosticLogger`.
- Tests: `tests/test_interaction_diagnostics.py` (new, unit-level: event validation, null-logger, helper no-op/error-swallowing, shared-file sanitized-payload proof); `tests/test_agent_runtime.py` additions (`test_runtime_correlates_interaction_events_across_context_model_and_tool_stages`, `test_runtime_emits_final_synthesis_event_on_budget_exhaustion`, `test_runtime_does_not_redact_token_counts_in_interaction_diagnostics`, `test_runtime_coordinates_context_budget_with_ollama_generation_limits`, `test_runtime_context_budget_coordination_survives_jsonl_redaction`).

## Acceptance decision

M5.2.13 is **automatically-accepted**. ADR-070 has genuine, solid implementation progress (interaction_id now correlates context/model/tool/synthesis/completion in one stream) but stays `Accepted` (not `Implemented`) pending M5.2.16 sign-off, per the standing plan. ADR-071 stays `Accepted`: FINDING-008's coordination gap is now closed (both numbers land in one observable record), but full "budget enforcement" semantics (e.g. actively rejecting/warning when `ollama_num_ctx` is inconsistent with `provider_context_window`) remain out of scope — this milestone is observation-only, matching the binding constraint that budgets stay platform-controlled and deterministic, not a new enforcement mechanism invented ad hoc.

## Residual item carried forward

`ai_assistant/infrastructure/sanitization.py`'s `redact_sensitive()` uses substring matching against its sensitive-keyword set, which produces false positives for any compound key containing "token", "prompt", "content", "response", or "auth" as a substring (two real instances hit and worked around in this milestone alone). The workaround (renaming just the colliding payload keys) is safe and now regression-tested, but the root cause is unfixed. Recommend a dedicated, carefully-tested fix (e.g. exact-key or word-boundary matching instead of raw substring) as part of M5.2.15's adversarial/regression pass or M5.2.16 closure — not attempted here, since a broad change to a shared security-critical sanitizer deserves its own focused review rather than being folded into an unrelated observability milestone.
