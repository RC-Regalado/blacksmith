# Milestone M3.8 Report - Implement `git_status`

Date: 2026-08-03

## Status

implemented-awaiting-human-review

## Summary

Implemented Python-side `git_status` for the local tool executor.

The tool uses fixed Git invocations:

- `git rev-parse --show-toplevel` to locate the repository root;
- `git status --porcelain=v1 -z -unormal` to return bounded structured status.

No shell, model-controlled Git subcommand, model-controlled flags, pager, hooks
or external diff tool were added.

## Security review

- No shell execution was introduced.
- No arbitrary Git subcommands, revisions, flags or environment are accepted from the model.
- Repository root must remain inside the configured workspace.
- Hidden and sensitive path components are omitted from returned entries.
- Git failures return sanitized typed errors.

## Residual risks

- Runtime permission assignment for new Phase 3 tools is still later integration scope.
- C toolserver does not implement `git_status` yet; M3.14 remains the milestone for making the C toolserver primary.
- `git_status` reports path metadata only; sensitive filenames are filtered, but Git metadata can still reveal non-sensitive filenames.
