## Combined changes

- Added `SessionId`, `DEFAULT_SESSION_ID` and session validation in `ai_assistant/agent/memory.py`.
- Updated `ConversationMemory` contract to `append(session_id, message)` and `history(session_id)`.
- Updated `AgentRuntime` to use a configured `session_id`.
- Updated CLI runtime construction to default to `default` and support `AI_ASSISTANT_SESSION`.
- Added SQLite `session_id` persistence, non-destructive migration for existing rows and index by `(session_id, id)`.
- Added tests for in-memory isolation, SQLite isolation, persistence across store instances and legacy migration to `default`.

## Architecture review

- Applicable ADRs: ADR-004, ADR-005, ADR-006.
- Conformance: sessions are explicit strings; SQLite is still behind the store adapter; runtime depends on the memory abstraction.
- Deviations: CLI reads `AI_ASSISTANT_SESSION` directly until the configuration/bootstrap milestones centralize environment loading.

## Security and safety review

- Findings: independent read-only review found no blocker.
- SQLite migration safety: existing rows receive `session_id TEXT NOT NULL DEFAULT 'default'`; no destructive migration.
- Residual risks: `validate_session_id()` rejects blank IDs but preserves surrounding whitespace.
