# M2.6 Report — Implement Deny-by-Default Tool Policy

## Status

implemented-awaiting-human-review

## Scope

Added a pure application-layer `DenyByDefaultToolPolicy`.

The policy validates:

- enabled/disabled tool execution;
- exact tool name against catalog definition;
- requested permission;
- request timeout;
- required and typed arguments;
- read byte limits;
- directory entry and depth limits;
- path policy denial mapping.

No executor, audit store, filesystem access or coordinator was added.

## Acceptance criteria

| Criterion | Evidence |
|---|---|
| Unknown tools are denied. | `deny_unknown_tool()` returns `unknown_tool`. |
| Malformed arguments are denied. | Missing/invalid argument tests return `invalid_arguments`. |
| Values above hard maximum are denied. | Timeout, read bytes, entries and depth tests deny with stable codes. |
| Denied requests never invoke an executor. | Test helper only invokes executor on `allow`; denied policy result leaves calls at 0. |
| Every denial has a stable reason code. | Tests assert exported reason-code constants. |
