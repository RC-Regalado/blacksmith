# M5.2.7 — interaction_id

## Status

automatically-accepted

## Scope

Remediate part of FINDING-009 (tool observability lacks interaction-level correlation): assign one `interaction_id` per conversational turn and propagate it through tool execution, recovery, diagnostics and audit. Full context-retrieval/model-call-level correlation (the rest of ADR-070) is deferred to M5.2.13 (end-to-end observability).

## Implementation evidence

- `ai_assistant/application/runtime.py`: `AgentRuntime.respond()` generates `self.last_interaction_id = uuid4().hex` once at the start of each turn, exposes it as an instance attribute, and every `ToolExecutionRequest` built during that turn (including the second, rejected request in the round-limit path) carries the same id.
- `ai_assistant/domain/tools.py`: `ToolExecutionRequest`, `ToolCallLogEvent`, `ToolAuditEvent` each gained an optional `interaction_id: str | None = None` field — plain observability metadata, not consulted by `ToolPolicy`/`PathPolicy` for any allow/deny decision.
- `ai_assistant/application/tool_coordinator.py` / `ai_assistant/application/tool_diagnostics.py`: `interaction_id` flows from the request into both the `ToolAuditEvent` and the `ToolCallLogEvent` unchanged.
- `ai_assistant/infrastructure/storage/sqlite_audit.py`: `tool_audit_events` table gained an `interaction_id TEXT` column, written via the existing parameterized (`?`) insert — no string interpolation.
- JSONL diagnostic logger required no code change: it serializes `ToolCallLogEvent` generically via `dataclasses.asdict`, so `interaction_id` appears in the JSONL payload automatically. Confirmed NOT used in filename construction (`_filename()` only takes `model`/`session_id`, both already sanitized).
- New tests: `tests/test_tool_diagnostics.py::test_runtime_tags_one_turns_events_with_a_shared_interaction_id` (two full `respond()` calls; all of turn 1's diagnostic rows share one id, turn 2 gets a different one), `tests/test_sqlite_audit.py::test_sqlite_audit_persists_interaction_id` / `test_sqlite_audit_allows_missing_interaction_id`.

## Independent validation evidence (2026-08-28)

- **Test agent**: PASS on all 5 checks; confirmed the shared/turn-scoped id test exists and passes end-to-end.
- **Security reviewer**: PASS — `interaction_id` is server-generated (never user input), persisted only via parameterized SQL, never used in filename/path construction; no regression across 183 security/tool-loop tests.
- **Architecture reviewer**: PASS — confirmed `interaction_id` is inert metadata with zero coupling to policy decisions, `AgentRuntime.respond()`'s public contract (`(user_input: str) -> Message`) is unchanged, and ADR-024's round-limit control flow is structurally identical to before.

## Acceptance decision

M5.2.7 is **automatically-accepted**. ADR-070 remains `Accepted` (not yet `Implemented` — full end-to-end correlation, including context-retrieval and model-call events, lands with M5.2.13).
