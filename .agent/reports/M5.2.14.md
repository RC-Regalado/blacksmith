# M5.2.14 — Expanded Metrics

## Status

automatically-accepted

Implemented together with M5.2.13 (same change set, same files). Full implementation evidence, independent validation evidence and acceptance decision are recorded in `.agent/reports/M5.2.13.md` — this file exists only to give M5.2.14 its own report pointer in the roadmap table.

## Scope delivered

New `ai_assistant/application/interaction_metrics.py`: frozen `InteractionMetrics` dataclass aggregating, per turn, everything the roadmap's M5.2.14 list asked to expose: `model_calls`, `prompt_tokens`/`output_tokens`/`finish_reason`/`truncated` (from the last `ModelResponse` of the turn), `tool_rounds`/`tool_requests`, `executor_operations`/`recovery_operations` (the latter derived as `executor_operations - 1` per result, since any result spending more than the baseline 1 operation did so via path recovery), `retrieval_attempted`/`knowledge_chunks_selected` (from the existing `ContextMetrics`).

`AgentRuntime.last_interaction_metrics` exposes this snapshot after every `respond()` call. `ai_assistant/interfaces/cli/app.py`'s `chat --metrics` now prints an `interaction: outcome=... model_calls=... finish_reason=... prompt_tokens=... output_tokens=... truncated=... tool_rounds=... tool_requests=... executor_operations=... recovery_operations=... retrieval_attempted=... knowledge_chunks_selected=...` line via `_print_interaction_metrics()`, tolerant (via `getattr`) of a duck-typed runtime double that lacks the attribute.

Dedicated tests: `tests/test_agent_runtime.py::test_runtime_reports_interaction_metrics_for_a_direct_model_answer` and `::test_runtime_reports_interaction_metrics_for_a_bounded_tool_loop` (hand-verified arithmetic, independently re-verified by the architecture reviewer); `tests/test_cli_app.py::test_cli_chat_metrics_print_interaction_metrics` and `::test_cli_chat_metrics_tolerates_runtime_without_interaction_metrics`.
